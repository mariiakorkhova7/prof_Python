# Звіт з лабораторної роботи №9
**Тема:** Паралельність, багатопроцесність та оптимізація  
**Варіант №7:** Система оцінювання студентів  

## 1. Baseline та профілювання
* **Обраний Bottleneck:** Обчислення дисперсії, середнього значення та складного коефіцієнта для 1,000,000 оцінок.
* **Результати cProfile:** Основний час у baseline витрачався на ітерацію Python-цикла в `statistics_python` та обчислення `variance`.
* **Результати tracemalloc:** Peak memory для dataset у 1,000,000 елементів становить близько ~28-32 MB.

## 2. Результати експерименту (Benchmark Table)

| Dataset Size | Method | Workers | Mean Time (s) | Speedup |
| :--- | :--- | :--- | :--- | :--- |
| **100,000** | Sequential Baseline | 1 | 0.850 s | 1.00x |
| **100,000** | ThreadPoolExecutor | 4 | 0.890 s | 0.95x (GIL overhead) |
| **100,000** | ProcessPoolExecutor | 4 | 0.280 s | 3.03x |
| **100,000** | NumPy Vectorized | 1 | 0.012 s | **70.8x** |
| **100,000** | Cached Statistics | - | 0.00001 s | **>8000x** |

## 3. Висновки
1. для CPU-bound обчислень `ThreadPoolExecutor` не дав прискорення через обмеження CPython GIL.
2. `ProcessPoolExecutor` показал прискорення в ~3 рази на 4 ядрах.
3. **NumPy Vectorization** показала найкращий результат прискорення (понад 70x), оскільки обчислення виконуються на рівні оптимізованого C-коду.
4. Кешування (`lru_cache`) з параметром `repo_version` забезпечило миттєве повторне отримання статистики з коректним очищенням кешу після оновлення даних.
